 # EHB TOKENOMICS + STAKING MODEL

 *(Validator + Ecosystem Economy Design)*

This document defines the **tokenomics and staking model** for the EHB blockchain. It explains how the native token powers:

- Network security (validators + nominators)
- Certification and verification fees
- Governance
- Ecosystem incentives

The native token is referred to here as **EHB** (or **EHBX** as a variant name).

---

## 1️⃣ TOKEN UTILITIES

The EHB token has multiple core utilities:

- **Validator staking**
  - Validators lock EHB to secure the network.
- **Transaction fees**
  - All on-chain operations (transfers, verification, certification, STL updates) are paid in EHB.
- **Certification payments**
  - CRB and industry certification fees are denominated in EHB.
- **Franchise verification fees**
  - On-chain verification and inspection records are paid in EHB.
- **Governance voting**
  - Token holders vote on protocol and parameter changes.
- **Network rewards**
  - Validators and nominators receive EHB as rewards for securing the chain.

The token is the **economic fuel** of the trust network.

## 3️⃣ STAKING SYSTEM (VALIDATORS)

Validators must **stake EHB** to participate in block production and consensus.

Example minimum validator stake:

```text
Minimum Validator Stake: 100,000 EHB
```

Flow:

```text
User stakes tokens
       │
       ▼
Validator node becomes active
       │
       ▼
Block validation & participation
       │
       ▼
Rewards earned in EHB
```

Staked tokens:

- Are **locked** while the validator is active.
- Can be **slashed** in case of misbehavior.

---

## 4️⃣ NOMINATOR SYSTEM (DELEGATED STAKING)

Not every user will run a validator node. The **nominator system** allows token holders to participate in staking.

Process:

- A user stakes tokens as a **nominator**.
- The nominator selects one or more **validators** to support.
- Supported validators secure the network and earn rewards.
- Rewards are **shared** between validators and nominators.

Example reward split:

- **Validator**: 60%
- **Nominators**: 40%

This allows:

- Broad **community participation** in security.
- Greater **decentralization** of stake.

## 5️⃣ VALIDATOR REWARD MODEL

Validators earn rewards from:

- **Block rewards** (network inflation).
- **Transaction fees**.
- A share of **certification and verification fees** paid on-chain.

Reward flow:

```text
Block Created & Finalized
      │
      ▼
Validator Reward Pool (EHB)
      │
      ▼
Validator + Nominators share
```

Incentives:

- Encourage validators to:
  - Stay online.
  - Behave honestly.
  - Run high-quality infrastructure.

---

## 6️⃣ SLASHING SYSTEM (SECURITY)

To protect the network, a **slashing mechanism** is applied when validators misbehave.

Slashable behaviors:

- Extended **downtime**.
- Creating or signing **invalid blocks**.
- **Equivocation** (double-signing).
- Attempted **network attacks**.

Example penalty ranges:

- **Minor fault** → ~1% stake slash.
- **Major fault** → 10–50% stake slash (or more in extreme cases).

Impact:

- Validators and nominators have strong incentives to:
  - Choose reliable operators.
  - Maintain robust setups.

## 7️⃣ TRANSACTION FEES

All EHB blockchain transactions require **fees in EHB**.

Example transaction types:

- Identity verification proof submission.
- Certificate issuance or renewal.
- Trust score (STL) update anchoring.
- Marketplace verification proofs.

Illustrative fee range:

```text
0.01 – 0.1 EHB per transaction
```

Fees:

- Go into the **reward pool** for validators and nominators.
- Help **prevent spam** and abuse.

This links **real-world certification demand** directly to **token demand**.
